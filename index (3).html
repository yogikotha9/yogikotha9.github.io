04 · Case studies

Problems I've solved

Six engineering problems from these roles: what was wrong, what I built, and what changed.

Delta Dental · 2024–now

An AI assistant that stays grounded

Problem
Members and providers called support with benefit questions that were already answered somewhere in long plan documents.
Approach
Built a RAG pipeline over plan documents and fee schedules in pgvector, orchestrated with LangGraph, with live claim lookups through function calling and MCP tools, answered by Claude on AWS Bedrock.
Result
Answers cite the plan they came from, and an evaluation suite of labeled questions checks accuracy and hallucinations before each release.
LangGraphBedrockpgvectorMCPSSE

Delta Dental · 2024–now

Claim lookups that don't wait in line

Problem
A single claim or estimate screen depended on several eligibility and benefits services, called one after another.
Approach
Rewrote the services in FastAPI with asyncio and httpx so calls run concurrently, added timeouts, retries, and circuit breakers, and cached benefit summaries in Redis.
Result
Screens load faster, and a slow dependency no longer takes the whole portal down with it.
FastAPIasynciohttpxRedis

Volkswagen · 2022–2024

Recalls matched before the car arrives

Problem
Dealers often learned about open recalls or warranty coverage only after a vehicle was already in the service bay.
Approach
Streamed connected-vehicle diagnostic events through Kafka into Python consumers that match fault codes against open recalls and coverage, with history kept in Cassandra.
Result
Dealers see open recalls and warranty eligibility in real time, before the appointment.
KafkaDjangoCassandraAKS

Volkswagen · 2022–2024

Spotting unusual warranty claims

Problem
Reviewers had no quick way to tell which warranty claims deserved a closer look.
Approach
Trained an anomaly model with scikit-learn and PyTorch, classified technician repair notes with Hugging Face Transformers, and tracked every experiment in MLflow.
Result
Unusual claims are flagged for review automatically, and repair notes route claims to the right team.
scikit-learnPyTorchHugging FaceMLflow

Nordstrom · 2021–2022

Inventory that holds up at holiday peak

Problem
Online availability and order routing had to stay accurate during the busiest sale days of the year.
Approach
Streamed store inventory through Kafka, served availability from Couchbase with Redis caching, checked locations concurrently with asyncio, and load-tested with Locust.
Result
Availability stayed in sync across stores and fulfillment centers through peak traffic.
KafkaCouchbaseRedisLocust

Citrix · 2019–2020

Heavy license jobs off the request path

Problem
License activation and usage aggregation slowed the portal while customers waited.
Approach
Moved the work to Celery workers on RabbitMQ, with entitlements in PostgreSQL and usage records in MongoDB.
Result
The portal stays responsive while heavy jobs run in the background.

05 · How I work

Habits I bring to a team

What stays the same from one team to the next.

Typed, tested Python

Type hints, Pydantic, and mypy, with Ruff and Black in CI, and pytest written before the code.

Async where it counts

asyncio for fan-out calls, Kafka and Celery for anything that shouldn't block a user.

AI with guardrails

Retrieval for grounding, evaluation suites before release, and cost and latency tracked like any other service.

Right database for the job

PostgreSQL for core data, MongoDB or Cassandra for flexible or high-volume data, Redis for hot reads.

Security built in

OAuth 2.0, JWT, and role-based access from day one, with HIPAA and PCI DSS rules where the data needs them.

Infrastructure as code

Terraform, Docker, and Kubernetes on AWS, Azure, or GCP, shipped through GitHub Actions, Jenkins, or GitLab.

Production you can see

Structured logs, Prometheus metrics, and Grafana, Datadog, or Splunk dashboards that show what broke and where.

Team first

Agile sprints, design reviews in Confluence, careful code reviews, and mentoring junior developers.
